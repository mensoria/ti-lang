## 1. 目的、权威与符合性

**TI-001.** Ti 是一门声明式业务语言，用于定义持久化实体、不变量、具有作用域的授权谓词、原子动作与业务事件。模型声明哪些变化合法；宿主提供身份、持久化、事务和投递能力。Ti 不是通用编程语言。

**TI-002.** 本草案中的“必须”“不得”“应当”“可以”分别对应英文 MUST、MUST NOT、SHOULD、MAY。[英文源文](ti-language-standard.md)是语言规范权威；本中文版逐条翻译相同规则，不建立独立语义。集成提案负责 Mensoria 绑定，示例仅供说明。冲突必须先在权威文档中解决，再启用相关功能。Mensoria 既有能力或历史测试不能证明 Ti 符合性。

**TI-003.** 符合性分为**校验器**、**纯求值器**和**宿主绑定**三个独立层次。校验器实现语法与静态规则；求值器实现确定性的候选状态求值；宿主绑定增加授权、持久化、并发、操作和事件投递。只有解析器的实现不得声称执行符合性。声明必须注明语言版次、配置档、实现指纹、限制和符合性证据。

**TI-004.** `approval-core/0.1` 包含本草案全部构造，每个动作只修改一个业务记录，每个实体只有一个状态机。未知语法和不支持的能力必须拒绝。不存在隐式扩展、原生语言逃逸、导入解析或网络依赖获取。

## 2. 源码与词法规则

**TI-005.** 源码必须是无 BOM 的有效 UTF-8。接受 LF 和 CRLF，拒绝单独 CR。空白仅包括 ASCII 空格、制表符、LF 和 CRLF。`//` 表示到行尾的注释；不支持块注释。源码和字符串值均不做 Unicode 规范化。

**TI-006.** 标识符匹配 `[A-Za-z_][A-Za-z0-9_]*`，区分大小写，最多 63 个 ASCII 字节。以下单词保留；关键字使用小写。`hasRole` 是区分大小写的内置成员名，不是关键字。

```text
module version entity field state initial final invariant policy create action
on from to allow require else set emit event true false null and or not
actor input self
```

**TI-007.** 整数字面量为 `0`，或可选负号后接非零数字及零个或多个数字。拒绝 `-0`、前导零、正号、分隔符、浮点和指数记法。数值必须在有符号 64 位范围内，包括 `-9223372036854775808`。模块版本为不超过 2147483647 的正整数。

**TI-008.** 字符串使用双引号及 JSON 风格转义：`\"`、`\\`、`\/`、`\b`、`\f`、`\n`、`\r`、`\t`、`\uXXXX`。禁止未转义的 U+0000–U+001F 控制字符。转义代理项对解码为一个标量；拒绝孤立代理项。不支持插值。字符串大小按解码后的 UTF-8 字节数限制，包括转义内容。

**TI-009.** 源码位置按从 1 开始的 Unicode 标量行列计数，结束位置为最后字符之后一位。制表符算一列；CRLF 算一次换行。词法采用最长匹配，先识别 `!=`、`==`、`<=`、`>=`。未知 token 和尾随源码都是错误。

## 3. 模块与命名

**TI-010.** 一个源单元以唯一的 `module NAME version N;` 开始，随后为声明。宿主在源码之外提供语言版次；模块版本与语言版次不同。本配置档的一个模型只有一个源单元。声明顺序不影响名称解析。

**TI-011.** 实体、事件、策略共享模块命名空间。原始类型名和内置函数名不得重新声明。每个实体 `E` 引入名义类型 `EId`，与任何声明名称冲突都是错误。每个实体恰好有一个创建声明。动作名在实体内唯一，且不能为 `Create`；宿主用 `Create` 标识创建操作。

**TI-012.** 字段名在实体或事件内部唯一。实体状态字段与业务字段共享命名空间。状态名在所属状态机内唯一。输入名在动作或创建声明内唯一。策略参数不能遮蔽保留名称或内置名称。

**TI-013.** 实体字段和状态字段不得使用平台保留名 `id`、`revision`、`created_at`、`updated_at`、`scope`、`model_version`，Ti 不能赋值这些属性。核心表达式可读取的平台属性只有 `self.id`。事件字段可以叫 `id`，但它只是载荷字段，不能覆盖事件信封。

## 4. 类型与值语义

**TI-014.** 核心字段、输入和事件类型为 `Bool`、`String`、`Int64`、`UserId` 及名义实体 ID，如 `LeaveRequestId`。`T?` 为不可空核心类型增加 null。拒绝嵌套可空后缀和可空实体。实体类型只用于策略参数，不用于持久化字段或动作输入。

**TI-015.** 状态具有所属实体私有的名义状态类型。不能通过输入传入状态，也不能用 `set` 赋值。状态名不得与实体业务字段、状态字段、原始类型或内置函数名冲突。裸状态名如 `Pending` 只在 `from`／`to` 中，或与当前实体状态字段比较并能获得类型时有效。缺少该类型操作数的两个状态常量比较存在歧义，必须拒绝。状态不是字符串。

**TI-016.** 赋值只接受完全相同类型、不可空 `T` 到 `T?`、或 null 到 `T?`。没有其他隐式转换。ID 是名义类型的不透明标量序列，不可与字符串互换。比较 ID 不代表获得关联对象访问权。核心表达式不能解引用关联记录。

**TI-017.** `Int64` 表示精确的有符号 64 位值。`String` 是 Unicode 标量序列；相等比较为精确、区分大小写的标量序列比较，不采用区域排序或规范化。布尔只有 true 和 false；禁止真值转换和 SQL 三值逻辑。

**TI-018.** `==`、`!=` 接受同一不可空标量或状态类型，或者可空操作数与 null 字面量。拒绝两个可空操作数相互比较，也拒绝可空操作数与非 null 值比较。`<`、`<=`、`>`、`>=` 只接受不可空 `Int64`。本配置档没有算术。

**TI-019.** `allow`、`require`、`invariant` 和策略表达式必须为 `Bool`。可空布尔不是谓词。null 检查后不进行流式类型收窄；需要时使用明确支持可空参数的内置函数。

### 内置函数

**TI-020.** 只支持下列函数与已校验策略调用：

| 函数 | 签名与行为 |
| --- | --- |
| `length(x)` | `String -> Int64`；计数 Unicode 标量 |
| `trim(x)` | `String -> String`；只去除首尾 U+0020、U+0009、U+000A、U+000D |
| `nonempty(x)` | `String? -> Bool`；null 或 trim 后为空则 false，否则 true；接受 String 的可空拓宽 |
| `actor.hasRole(x)` | 字符串字面量 -> Bool；检查可信作用域角色集合的精确成员关系 |

**TI-021.** 角色字面量为非空 ASCII 字符串，最多 128 字节。`actor.id` 类型为 `UserId`。操作者 ID 与角色必须来自同一个带身份域和作用域绑定的可信身份快照，不是动作输入。宿主必须另行定义角色分配、撤销与业务租户绑定。平台管理员身份不隐式授予业务角色。

## 5. 表达式与求值上下文

**TI-022.** 优先级从高到低为：括号／成员访问／函数调用；前缀 `not`；单个比较；`and`；`or`。布尔二元运算左结合，按从左到右短路。拒绝链式比较。表达 `not (a == b)` 时必须有括号。所有表达式均须静态校验，包括运行时不会执行的分支。

**TI-023.** 表达式上下文是封闭的：

| 上下文 | 可用名称 |
| --- | --- |
| 不变量 | 当前实体的裸字段／状态字段名、有类型状态常量、纯内置函数 |
| 策略 | 实体参数及其标量字段／状态／ID、actor、其他已校验策略、纯内置函数 |
| 创建 allow／require／set | input、actor、纯内置函数；无 self 或实体策略实参 |
| 动作 allow／require／set | 旧 self、input、actor、策略、纯内置函数 |
| 事件载荷 | 候选 self、input、纯内置函数；无 actor 或策略 |

不变量不得依赖 actor、input、策略、时间或外部数据，迁移和维护校验时其意义必须保持稳定。策略恰有一个不可空实体参数，返回 Bool。调用只能传入类型匹配的 self 或实体参数。不能在表达式中构造实体值。事件不能包含整个实体或隐式记录序列化。

**TI-024.** 策略调用图必须无环。策略不能查询存储。函数必须确定且无副作用。访问路径限于 `input.FIELD`、`self.FIELD`、`PARAM.FIELD`、`actor.id`、`self.id`／`PARAM.id`。拒绝其他链、任意方法调用、索引、动态名称和反射。裸字段名仅在不变量中有效。

**TI-025.** 达到声明的求值预算必须拒绝动作，不能发生部分业务提交。求值限制是执行配置档的一部分。宿主不得因预算耗尽而静默改变结果或跳过谓词。

## 6. 实体与状态机

**TI-026.** 实体声明零个或多个字段、恰好一个状态机、零个或多个具名不变量。至少有一个状态，恰好一个初始状态；任何状态不得同时标记 initial 和 final。未标记状态可以有出向动作。没有隐式转换或默认动作。

**TI-027.** 终态不得有出向动作，包括同状态动作。非终态允许同状态动作。多个动作可以有相同起止状态，由调用者明确选择动作；执行器不得按声明顺序或谓词匹配自动选择。

**TI-028.** 每次成功创建或动作都必须产生满足全部不变量的记录，不变量按源码顺序检查。旧记录已经无效时，必须在普通业务求值前以 `TI_RECORD_INVALID` 拒绝；普通动作不能静默修复坏数据。特权修复需要独立宿主维护契约及修复后校验。

**TI-029.** 校验器应当诊断不可达状态，以及没有出向动作的非终态。不得宣称谓词必然可满足、审批策略正确，或状态图保证现实流程最终完成。

## 7. 创建与原子动作

**TI-030.** 创建声明包含有类型输入、恰好一个 allow、零个或多个前置要求，最后是赋值。创建没有来源转换、self 或事件。每个必填不可空字段必须初始化一次。省略的可空字段初始化为 null。状态采用初始状态；宿主为已接纳操作生成稳定逻辑 ID，重试必须复用原创建结果和 ID。

**TI-031.** 动作依次声明可选输入、一个来源和目标、恰好一个 allow、零个或多个 require、赋值和事件。require 的错误标签是匹配 `[a-z][a-z0-9_]{0,62}` 的字面量，同一操作内不得重复。空输入括号和省略括号都表示无输入。

**TI-032.** 赋值只能指向业务字段，每字段一次。未赋值字段保留旧值。所有右值读取同一旧记录和输入，然后同时应用。因此类型兼容的 `set a = self.b; set b = self.a;` 会交换两字段。赋值不引入变量。事件观察新记录，而非赋值中间状态。

**TI-033.** 新动作的逻辑执行顺序为：

1. 校验请求结构、有类型输入、可信身份与目标作用域。
2. 按当前结果访问规则核对原操作／幂等键。
3. 新操作解析活动模型，检查预期制品身份。
4. 执行平台动作／数据授权，取得一致的旧记录。
5. 检查业务 allow、预期记录版本，再检查来源状态。
6. 检查旧记录不变量，再按源码顺序检查 require。
7. 求值并应用赋值及状态转换，形成候选记录。
8. 检查候选不变量，按源码顺序求值并校验事件类型。
9. 原子提交记录、版本变化、操作结果、审计和 outbox。
10. 在披露响应前执行宿主结果发布授权。

创建将第 4–8 步替换为平台创建授权、业务 allow、require、初始化和候选不变量检查。依赖数据的步骤必须处于同一事务，或由将所有观察依赖绑定到提交的等价协议保护。检查后单独执行无保护 PATCH 不符合规范。模型读取受保护字段必须获得范围受限的宿主求值能力，不得隐式取得管理员权限或向调用者披露字段。无法提供必要求值能力时，模型激活必须失败。

**TI-034.** 纯求值期间 actor 快照固定。宿主必须在提交与结果发布处执行声明的撤权／admission 协议；快照不是永久授权。外部角色存储需要明确资格化的一致性协议。Ti 不暗示外部身份提供方与环境数据库之间存在原子事务。

**TI-035.** 现有记录动作必须带预期 revision。每次成功动作版本前进一次，即使同状态或字段值未变。revision 是宿主不透明 token，客户端不能推算下一个版本。同一版本的两个转换不能都提交。冲突不得触发换新键、基于最新状态自动执行。

**TI-036.** 宿主必须防止所有公开替代写入口绕过规则。本配置档拒绝对 Ti 受管集合执行通用 CRUD、SQL 写、批量写和导入。创建和草稿编辑也走动作。Schema 变更、原生维护和特权修复需要另行授权与审计的协议。编译不能单独保证此限制，这是宿主绑定符合性要求。

## 8. 事件、审计与外部副作用

**TI-037.** 每次 emit 必须引用已声明事件，并为每个字段恰好提供一个可赋值表达式。事件可空字段也必须明确提供值或 null，不存在隐式省略。一个事件可以多次发出，以源码序号区分。

**TI-038.** 事件信封包含稳定事件 ID、原操作 ID、可信作用域、精确模型制品、事件类型、发出序号、目标逻辑 ID 和已提交记录版本。载荷不能覆盖信封元数据。同一操作重试不得生成新事件 ID 或重复 outbox 条目。

**TI-039.** 事件持久化必须与业务状态原子提交。投递至少一次，使用稳定 ID 和消费者去重。宿主声明重试／保留及失败投递处理，不承诺全局投递顺序或外部副作用恰好一次。审批完成和通知送达是不同状态。消费者失败不回滚业务记录。

**TI-040.** 事件载荷是受保护数据。发布／消费必须执行宿主授权、披露、保留和撤权规则。emit 不授予发邮件、导出或调用模型的权限。不可逆外部副作用需要独立适配器契约；不能因至少一次传输就盲目重放结果未知的外部操作。

**TI-041.** 审计绑定作用域、actor 身份域／ID、模型制品、动作、操作、目标 ID，以及前后 revision 和状态。创建没有旧状态／版本。审计不得自动复制凭据或全部请求／记录内容。审计持久化失败阻止业务提交。拒绝尝试可进入独立安全日志，不属于成功业务动作审计。

## 9. 请求值、幂等与可观察结果

**TI-042.** 传输绑定必须无精度丢失或 ID 混淆地表达有类型值。核心逻辑值编码示例：

```json
{"type":"Int64","value":"3"}
```

| 类型 | value 成员 |
| --- | --- |
| Bool | JSON 布尔 |
| String | JSON 字符串 |
| Int64 | 规范十进制字符串，遵循整数字面量规则 |
| UserId | 不透明字符串，可信上下文绑定身份域 |
| EId | 不透明字符串，类型标签为 EId |
| Null | `{"type":"null"}`，没有 value 成员 |

输入为名称到带类型值的对象。所有声明输入必须存在，可空输入也须明确传 null。拒绝缺失、额外、重复键、未知标签／成员及不兼容值。空 ID 无效。禁止结构化记录身份和原生数据库选择器。

**TI-043.** 绑定必须要求原始幂等键、预期模型制品，以及现有记录的逻辑 ID 和预期 revision。作用域和 actor 不能通过输入提供。幂等键为 1–128 个 `[A-Za-z0-9._:-]` ASCII 字符。键查找作用域包括可信环境 incarnation 和 principal 身份域／ID；该范围内键只绑定一个操作。

**TI-044.** 请求指纹绑定语言版次／配置档、模块／制品、实体／动作、目标或创建标记、预期版本或创建标记、可信作用域／incarnation／actor 和全部有类型输入。该逻辑元组的精确规范字节编码必须版本化，才能声称宿主符合性。禁止无明确分帧的分隔符拼接。对象键顺序不重要，字符串不做规范化，ID 保留名义类型。原始 JSON 哈希不能代替该编码。

**TI-045.** 同键同指纹核对原操作；不同指纹在当前授权检查后返回冲突。已接纳操作必须可持久核对；无法确认是否提交时，基础设施不得报告业务拒绝。接纳前失败可以无 operation 返回，但须明确接纳阶段。

**TI-046.** 绑定至少区分 `committed`、`rejected`、`pending`、`unknown` 观察结果，并明确表达原结果过期。接纳后在可观察时包含原操作引用。接纳后确认拒绝将原键绑定到该拒绝结果，重试不在新数据上重新求值。拒绝不得生成业务记录、业务审计或业务事件，但可以持久化操作收据和安全日志。unknown 表示结果未确认，不代表回滚或允许重放。取消／超时／断连不能证明拒绝，也不能撤销提交。

**TI-047.** 收据过期不得让旧键重新可执行。宿主保留键墓碑或退役其作用域，防止旧键被当成新写。结果获取始终执行当前访问规则。原调用者可能已无权查看一个已提交操作的结果。不得用最新记录状态静默替代原结果；保留快照仍受当前字段披露规则约束。

## 10. 模型制品、激活与演进

**TI-048.** 校验产生冻结制品，绑定精确 UTF-8 源码、源码摘要、版次／配置档、编译器指纹、有类型 IR 摘要、模型名称与版本、依赖绑定、资源限制和能力要求。摘要采用有明确域／版本分帧的 SHA-256。宿主必须固定清单／IR 序列化契约，源码哈希不是完整制品身份。编译不得执行动作或修改 Schema。

**TI-049.** 已发布模型版本在可信项目作用域内不可变。注释变化也改变源码制品，已发布后必须使用新版本。环境只能激活与 Schema 映射、角色契约、策略和安全 generation 绑定的可信已校验制品。调用者不能通过旧制品选择宽松规则。

**TI-050.** 核心激活过程停止接纳新业务写，按宿主协议核对或围栏隔离在途操作，检查旧数据和受影响绑定，再以 CAS 切换活动制品并重新开放。不兼容变化需要明确审查的数据／Schema 迁移。不暗示自动回滚、在线热切换、跨环境事务或历史重写。旧操作保留原制品引用用于核对。

**TI-051.** 删除字段／状态／动作、加强不变量、变更角色绑定／谓词／事件载荷均需要影响审查。新增语法不能单独证明向后兼容。已提交事件保留原 Schema／制品，消费者声明接受的版本。恢复必须保留或重新资格化模型绑定，并在恢复写入前执行 Mensoria 当前安全／incarnation 规则。

## 11. 诊断与资源限制

**TI-052.** 诊断包括稳定错误码、阶段、脱敏消息及可定位时的源码范围。执行错误在已接纳且可观察时包括原操作引用及重试／核对提示。require 标签可按宿主披露策略作为可选公开细节。内部求值顺序不授予披露隐藏记录、角色、字段或状态的权利。

| 错误码 | 含义 |
| --- | --- |
| TI_SYNTAX | 无效词法／语法输入 |
| TI_NAME | 未知、保留、重复或歧义名称 |
| TI_TYPE | 无效类型、运算、调用或赋值 |
| TI_MODEL | 无效状态／创建／动作结构 |
| TI_EFFECT | 禁止的副作用或依赖 |
| TI_LIMIT | 超出静态或运行预算 |
| TI_INPUT | 请求／输入编码无效 |
| TI_ACCESS_DENIED | 平台／业务拒绝或隐藏目标 |
| TI_MODEL_STALE | 预期模型与活动绑定不符 |
| TI_REVISION_CONFLICT | 记录版本已改变 |
| TI_STATE | 来源状态不符 |
| TI_RECORD_INVALID | 旧数据违反活动模型 |
| TI_REQUIRE | 动作前置要求不满足 |
| TI_INVARIANT | 候选违反不变量 |
| TI_IDEMPOTENCY_CONFLICT | 键已绑定不同输入 |
| TI_OUTCOME_UNKNOWN | 原提交结果未确认 |
| TI_RESULT_EXPIRED | 原结果不再保留；不允许重放 |
| TI_DEPENDENCY_UNAVAILABLE | 宿主依赖不可用；结果须另外判断 |

宿主可将私有状态／版本错误收敛为访问拒绝。供运维保留的内部诊断不得从公开 API 泄露。

**TI-053.** 实现必须公布确定性静态／求值预算，在失控分配或栈递归前拒绝超限输入。基线限制为：

| 预算 | 上限 |
| --- | --- |
| 源单元 | 256 KiB |
| 标识符 | 63 ASCII 字节 |
| 解码字符串值／字面量 | 16 KiB |
| 单个不透明 ID | 256 UTF-8 字节 |
| 表达式嵌套 | 64 |
| 声明数，不含嵌套字段／状态 | 256 |
| 每实体／事件字段数；每操作输入数 | 各 64 |
| 每实体状态数 | 64 |
| 每操作 require／每实体 invariant | 各 64 |
| 每动作 emit | 16 |
| 每操作展开表达式节点求值次数 | 100000 |
| 编码输入／事件载荷总量 | 各 128 KiB |

访问一个表达式 AST 节点计一步，重复策略体求值重复计数，短路跳过节点不计。allow、旧／新不变量、require、赋值、事件共享一次操作的预算。宿主另行公布并强制记录、角色集合、事务时长、输出字节和投递资源限制；超时本身不证明回滚。不同限制必须使用明确命名配置档，不能静默改变基线。

## 12. 排除项与扩展纪律

**TI-054.** 本版不包含算术、金额／日期、集合表达式、连接、跨记录策略、用户通用函数、导入、循环、任意 Rust／原生代码、SQL、文件／网络、计时器、多记录动作、会签／委派、Saga 和分布式事务。扩展必须在接受前定义语法、类型、副作用、作用域、限制、版本、失败语义和符合性案例。数据库或 Rust 库能做到，不代表宿主能力已启用。

## Appendix A. 规范语法

EBNF 用引号表示终结符、`{ X }` 表示重复、`[ X ]` 表示可选、`|` 表示替代。IDENT、INT、POSINT、STRING 遵循上述词法规则。编号条款中的结构与类型约束同时适用。声明结束大括号后不接受分号。

```ebnf
source       = "module", IDENT, "version", POSINT, ";", { declaration } ;
declaration  = entity | policy | creation | action | event ;
entity       = "entity", IDENT, "{", { field }, state, { invariant }, "}" ;
field        = "field", IDENT, ":", type, ";" ;
type         = IDENT, [ "?" ] ;
state        = "state", IDENT, "{", state_item, { state_item }, "}" ;
state_item   = IDENT, [ "initial" | "final" ], ";" ;
invariant    = "invariant", IDENT, ":", expression, ";" ;
policy       = "policy", IDENT, "(", IDENT, ":", IDENT, ")", "=",
               expression, ";" ;
creation     = "create", IDENT, "(", [ parameters ], ")", "{", allow,
               { requirement }, { assignment }, "}" ;
action       = "action", IDENT, [ "(", [ parameters ], ")" ], "on", IDENT,
               "{", transition, allow, { requirement }, { assignment },
               { emission }, "}" ;
parameters   = parameter, { ",", parameter } ;
parameter    = IDENT, ":", type ;
transition   = "from", IDENT, "to", IDENT, ";" ;
allow        = "allow", expression, ";" ;
requirement  = "require", expression, "else", STRING, ";" ;
assignment   = "set", IDENT, "=", expression, ";" ;
emission     = "emit", IDENT, "{", { event_value }, "}" ;
event_value  = IDENT, "=", expression, ";" ;
event        = "event", IDENT, "{", { field }, "}" ;
expression   = disjunction ;
disjunction  = conjunction, { "or", conjunction } ;
conjunction  = comparison, { "and", comparison } ;
comparison   = unary, [ compare_op, unary ] ;
compare_op   = "==" | "!=" | "<" | "<=" | ">" | ">=" ;
unary        = { "not" }, primary ;
primary      = INT | STRING | "true" | "false" | "null"
             | reference | call | "(", expression, ")" ;
reference    = name, [ ".", IDENT ] ;
name         = IDENT | "self" | "input" | "actor" ;
call         = IDENT, "(", [ arguments ], ")"
             | "actor", ".", "hasRole", "(", STRING, ")" ;
arguments    = expression, { ",", expression } ;
```

裸 self 或策略参数只能作策略调用实参；裸 actor／input 不是值。reference／call 由后续 token 区分；通用调用形式不授权任意函数。目标状态和状态比较均在所属实体内解析。

## Appendix C. 规范逻辑指纹编码

为消除 TI-044 歧义，核心指纹字节采用下述分帧。`U32(n)` 是四字节无符号大端整数。`F(tag, bytes)` 是一个 ASCII 标签字节、`U32(字节长度)` 和精确载荷字节。文本使用无规范化 UTF-8。长度溢出必须拒绝。

有类型值编码如下：

- Bool：`F('b', "true")` 或 `F('b', "false")`，内容为 ASCII。
- String：`F('s', 解码后 UTF-8 内容)`。
- Int64：`F('i', 规范 ASCII 十进制)`。
- UserId：`F('u', 不透明 UTF-8 内容)`。
- 实体 ID：`F('e', F('t', 实体类型名) || F('v', 不透明 ID))`。
- Null：`F('n', 空字节)`；声明的可空类型来自制品。

`||` 表示字节连接，不是语言表达式。输入条目按 ASCII 名称字节排序，编码为 `F('p', F('k', 名称) || 有类型值)`。输入块为 `F('x', 已连接条目)`。排序前拒绝重复名。JSON 空白、转义写法和对象顺序不影响编码。

请求元组严格按如下顺序连接：

1. `F('d', "ti.request/0.1")`；
2. `F('l', 语言版次)`、`F('p', 配置档)`；
3. `F('s', 宿主作用域 token)`、`F('g', 宿主 incarnation token)`；
4. `F('a', principal 身份域 token)`、`F('u', principal ID token)`；
5. `F('m', 模块名)`、`F('v', 规范模块版本十进制)`；
6. `F('h', 精确预期制品身份 token)`；
7. `F('e', 实体名)`、`F('c', 动作名或 "Create")`；
8. `F('r', 逻辑记录 ID)`、`F('q', 预期 revision token)`；创建则两者载荷均为空；
9. 输入块。

指纹为该元组的 SHA-256。宿主作用域 token 必须无歧义绑定组织、项目、环境及必要的业务租户；这些 token、身份域、版本、制品身份 token 的版本化编码由绑定定义，不能从不可信输入推断。普通记录 ID 和 revision token 不得为空。幂等键是查找键，不进入请求指纹。摘要仅用于相等判断，不是授权凭据或公开披露格式。

基础分帧夹具 `F('i', "3")` 的十六进制为 `69 00 00 00 01 33`。完整宿主绑定必须公布采用其具体 token 编码的完整元组／摘要夹具，才能声称宿主符合性。
