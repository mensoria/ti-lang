# Mensoria 集成与职责归属

状态：集成提案，并非已实现能力。[Ti 标准草案](ti-language-standard.zh-CN.md)负责语言语义。

## 体系归属

Ti 是 Mensoria 的声明式业务语言。模型校验、版本管理和动作执行属于共享 Rust 应用核心中的业务语义模块，不要求独立服务、数据库内核或调度器。

```text
Studio / SDK / 应用
        ↓
Ti 校验 + 不可变模型制品 + Action API
        ↓
Identity / Policy / Schema / 受控命令执行
        ↓
Record + Operation + Outbox + 审计
        ↓
SurrealDB 环境数据库
```

| 所有者 | 职责 |
| --- | --- |
| Ti 编译器 | 语法、类型、纯表达式、状态／动作语义、制品 |
| Ti 模型服务 | 版本、依赖、兼容性、显式激活 |
| Ti 动作执行器 | 前置条件、候选状态、不变量、事件载荷 |
| Mensoria Identity／Policy | 可信 actor、作用域、当前平台权限 |
| Mensoria Schema | 逻辑字段、编解码、迁移与物理映射 |
| Mensoria 命令基础设施 | 安全 admission、版本检查、原子提交、原操作／键核对 |
| Mensoria Runtime | 复用现有 outbox 投递与任务执行机制 |
| Mensoria Studio | 编辑、校验反馈、状态图、激活审查、操作检查 |

## 既有基础与新增工作

已检查的 Mensoria 原型文档记录了受控记录命令、版本检查、持久操作、outbox 写入和未知结果核对。这些是集成输入，历史或本地资格化不能证明 Ti 动作或新部署已通过验证。

新增工作包括模型制品与激活、表达式校验／求值、动作授权和状态转换、不变量强制、原子动作命令、业务事件，以及关闭替代写入口。已有 CRUD 不证明这些行为已实现。

## 绑定与权限

复用可信组织／项目／环境绑定和记录身份。Ti 源码或动作输入不能携带物理数据库或原生 record token。平台作用域与应用可选业务租户不同；后者需要显式 Schema 与策略设计，Ti 不自动发明租户模型。

业务授权只能收紧平台权限，不能访问被平台拒绝的记录或字段。角色契约必须明确业务角色由哪个身份域及权威提供；平台成员不得静默获得应用用户特权。

遵循 Mensoria 当前会话、admission、撤权和结果发布规则，不能弱化为永久有效请求快照。Schema 迁移与模型激活是维护／控制操作；普通 Action API 不得获得 DDL 或 root 能力。

## 防止绕过

MVP 中 Ti 受管集合的公开写入只走动作，包括创建和草稿编辑。通用 CRUD、批量、SQL 写与导入入口必须拒绝直接写入，除非另行审查协议能保证等价语义。读取继续受平台授权保护。

若其他入口能直接修改 status，语言级 allow 就没有足够保证。限制必须放在共享命令／存储能力边界，而不只放在 Studio。特权修复单独授权、审计，并在之后校验模型。

## 与 SQL 的关系

Mensoria SQL 是数据查询／修改前端；Ti 定义合法业务变化。两者复用应用核心，Ti 无需先转译 SQL。已检查 SQL 规范仍是提案，不是已启用端点。

SQL 可通过已发布绑定读取获授权的业务字段，写入必须遵守受管集合限制。Ti 表达式独立版本化，不得静默继承 SQL NULL 或 SurrealQL 真值语义。

## 动作请求提案

动作请求包含逻辑目标 ID、动作名、有类型输入、预期记录版本、预期模型制品 token 和原始幂等键。这些是概念字段，并非已发布 HTTP 契约。

宿主解析活动制品，新操作拒绝过期模型预期。同键核对指向原制品与结果，仍执行当前结果访问规则。状态、操作结果、审计和 outbox 必须原子持久化；外部副作用发生在提交之后。
