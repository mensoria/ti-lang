# 交付阶段与验收

状态：拟议顺序，尚无实现里程碑完成。[标准草案](ti-language-standard.zh-CN.md)定义基线，[符合性案例](conformance.zh-CN.md)定义实现证据。

## 阶段一：冻结语义契约

审查并冻结语法、表达式和状态符号类型、诊断、规范输入编码、身份角色绑定、资源限制、制品格式及激活兼容性。先形成批准的源码到 IR 示例与反例诊断，再开始依赖这些决策的执行实现。

## 阶段二：模型校验

实现解析器与语义校验器，生成不可变、版本化 IR。接受审批示例，拒绝缺少 allow、错误事件载荷、未知状态、重复赋值、禁止调用和超深／畸形输入。编译成功不授予存储或部署权限。

## 阶段三：纯动作求值

给定可信上下文、旧记录和有类型输入，返回候选记录及事件，或结构化拒绝。验证同时赋值、旧记录前置条件、新状态不变量、null 和确定性。此阶段不证明持久化或并发性质。

## 阶段四：集成一个真实审批模型

在 Mensoria 固定后端上使用一个环境和一个受管集合。实现受控原子动作，关闭通用写绕过，沿现有维护边界激活模型。先交付最小 SDK 链路，再增加可视化编辑器。

| 场景 | 必需结果 |
| --- | --- |
| 合法创建／编辑／提交／批准 | 正确版本、状态、审计与事件 |
| 申请人自批 | 拒绝，无业务变更 |
| 无平台数据权限 | 业务 allow 不能覆盖拒绝 |
| 错环境／业务租户 | 无越权或存在性泄露 |
| 输入或新状态不变量不满足 | 原子拒绝 |
| 并发批准与撤回 | 同一来源版本仅一个成功 |
| 同键相同请求 | 原授权结果，无重复事件 |
| 同键不同输入／模型 token | 幂等冲突 |
| 提交响应丢失 | 未知结果，核对原操作 |
| outbox／审计写失败 | 业务提交不部分成功 |
| 消费者失败 | 业务保持提交，稳定事件按契约重试 |
| CRUD／SQL／批量写 | 不得绕过受管集合规则 |
| 旧模型／不兼容激活 | 拒绝或阻止直接激活 |
| 已撤权用户取旧结果 | 执行当前结果发布策略 |

## 阶段五：编写体验

在 Studio 增加校验、自动状态图、模型差异、激活审查、动作／操作检查。已确认业务状态与待投递事件状态分别呈现。不能把请求超时显示为审批失败证明。

## 延后范围

多对象动作、委派、多级／会签、计时器、外部付款、任意宿主扩展、AOT、热替换及金额／日期编解码均另立语义与失败契约。

文档审查、本地测试、后端故障检查、CI 和业务验收分别报告。合成或纯求值测试不证明事务、恢复、撤权或生产就绪。
